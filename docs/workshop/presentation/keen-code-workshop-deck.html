  • Extensible. MCP, skills, subagents, memory.

03 · How it was built

A coding agent, built by coding agents

All code is written by AI agents. The human has one job: specify, review, and steer.

1 · Spec

Prompt

Requirements written as markdown. "Ask permission before reading, 1 MB limit, respect the file guard."

2 · Plan

Design doc

The agent produces a plan with contracts and flow diagrams. I review it and push back.

3 · Task

Implement

Work is broken into steps, each approved before the next begins. Tests included.

4 · Review

Correct

Human and agent review. Fixes land in the same iteration, then the cycle repeats.

  • Five development phases, 133 prompt and output docs saved chronologically, so the thought process is auditable.

05 · Design decisions

Six choices that shape how it behaves

  • 10 built-in tools: read_file, write_file, edit_file, glob, grep, bash, web_fetch, ask_user, delegate_task, call_mcp_tool.
  • Hashline edits: each line carries N:HASH|; stale anchors are rejected, not applied.
  • Turn memory: later turns see a bounded summary of tool calls, not raw outputs.
  • Skills and MCPs - MCPs interfaced using generated skills.
  • Subagents: up to 10 bounded tasks in parallel.
  • Auto-router: Jev-like System One model integration - more use-cases in the roadmap.
